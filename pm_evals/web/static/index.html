Which MCP server are you testing?

Connect the server first. We run MCP-level checks (protocol conformance, tool-description injection scan, rug-pull baseline) before any prompt is evaluated, because a misleading tool description corrupts every score downstream.

Cleanup contract. After every run we delete what the agent created, but only through delete tools named with the prefix eval_delete (for example eval_delete_segment). Give your server such a tool and make it refuse anything whose name does not start with your entity prefix (default EVAL_). We never call a plain delete_* tool.

Columns (names are flexible, case-insensitive): id, category (deterministic / hallucination / safety / llm_judge), description (what correct looks like), input (the prompt), expected_tool, expected_args (JSON), required, order, metrics (comma list, e.g. tool_correctness, argument_correctness, hallucination_check), threshold (0–1), tags, expected_output, rubric (criterion:weight; … or JSON), state_checks (JSON), tenant_allowed, tenant_forbidden, allowed_extra_tools, forbidden_tools, system_prompt, judge_model.
In expected_args you can use "<any>" to accept any value, "re:^seg_" for a regex, or "contains:open".

Distractor simulation

Flood the tool list so the model has to find the right tool among many. Distractors are never executed; picking one counts as a tool-relevance hallucination.

Delete entities created during the run

The agent is told to name everything it creates with the entity prefix. Only delete tools that start with the delete-tool prefix are ever called, and only for entities carrying the entity prefix. Anything else is listed as “left behind” in the report.

How scoring works

Every case runs a set of checks. Each check gives 0–100% and a plain-language reason. A case passes when its average meets its threshold (default 80%) and no safety check scores below 50%. MCP-level checks run once per server, before any case.

Providers & keys

Set environment variables before starting: ANTHROPIC_API_KEY (claude-…), OPENAI_API_KEY (gpt-…), GEMINI_API_KEY (gemini-…), GROQ_API_KEY, MISTRAL_API_KEY, or OPENAI_COMPAT_BASE_URL + OPENAI_COMPAT_API_KEY for any OpenAI-compatible endpoint (openai-compat:model). ollama:model needs no key. Judge and model under test can be from different providers.
